Introduction

The AyushSetu Terminology Microservice is a lightweight, FHIR-compliant service that bridges India’s NAMASTE traditional medicine terminologies with WHO ICD-11 TM2 and Biomedicine.

✓ NAMASTE (Ayurveda, Siddha, Unani)
✓ ICD-11 TM2 disorders
✓ ICD-11 Biomedicine
✓ WHO Ayurveda Terminologies
✓ FHIR R4 compliant
✓ Online + Offline modes

EMR vendors can plug this service in as a terminology plugin to support:

  • Auto-complete of NAMASTE codes inside clinical UI
  • Dual coding: NAMASTE ↔ ICD-11 TM2 ↔ Biomedicine
  • FHIR Bundle upload with double-coded conditions
  • Semantic search and mapping using modern embedding models

Authentication (ABHA-style Mock)

The problem statement requires OAuth 2.0 with ABHA-based identity and audit metadata. For the SIH prototype, we use a mock validator:

Request Header

Authorization: Bearer <ABHA-like-token>
  • Any non-empty bearer token is treated as valid.
  • Token subject is logged into audit metadata.
  • Production deployment can swap this with actual ABDM OAuth validation.

Terminology Sets

The microservice loads and serves multiple terminology systems:

  • NAMASTE CodeSystem ~4,300 disorder concepts across Ayurveda, Siddha, and Unani.
  • ICD-11 TM2 Disorders ~310 disorder codes fetched from WHO ICD API and cached.
  • ICD-11 Biomedicine Optional dual-coding link for insurance/analytics.
  • WHO Standardised International Ayurveda Terminologies
  • Index Terms (MMS Browser) Used as multilingual bridge and validator for mappings.

Returns an expansion over the NAMASTE CodeSystem filtered by the search text. Designed for use in EMR autocomplete widgets.

/translate (ConceptMap-powered)

1. NAMASTE → ICD-11 TM2

POST
/translate/namaste-to-tm2
FHIR $translate-style Uses ConceptMap + semantic engine

Takes a NAMASTE code and returns the best matching TM2 code with a confidence score.

Example Request

POST /translate/namaste-to-tm2
Content-Type: application/json
Authorization: Bearer demo-token

{
  "code": "AAA-3.9"
}

Example Response

{
  "from": "NAMASTE",
  "inputCode": "AAA-3.9",
  "bestMatch": {
    "code": "SL40",
    "display": "Bronchial asthma disorder (TM2)",
    "equivalence": "related",
    "confidence": 91.4,
    "comment": "auto-mapped; cosine=0.937"
  }
}

2. ICD-11 TM2 → NAMASTE (reverse)

POST
/translate/to-namaste
FHIR-like reverse lookup Top 10 mappings

Returns up to 10 NAMASTE codes that map to the given TM2 code, ordered by descending confidence.

Example Request

POST /translate/to-namaste
Content-Type: application/json
Authorization: Bearer demo-token

{
  "code": "SL40"
}

Example Response

{
  "from": "ICD-TM2",
  "inputCode": "SL40",
  "mappedTo": [
    {
      "namasteCode": "D",
      "namasteDisplay": "Amrāḍ-i-Niẓām-i-Tanaffus",
      "equivalence": "equivalent",
      "confidence": 95.2,
      "comment": "auto-mapped; cosine=0.937"
    },
    {
      "namasteCode": "D-6",
      "namasteDisplay": "Rabw",
      "equivalence": "equivalent",
      "confidence": 94.1,
      "comment": "auto-mapped; cosine=0.935"
    }

/bundle/upload (Dual-coded encounters)

POST
/bundle/upload

Accepts a FHIR R4 Bundle that includes Condition resources coded with both:

  • NAMASTE terminologies
  • ICD11TM2 / Biomedicine codes

  "code": {
    "coding": [
      {

        "display": "jvara (fever)"
      },
      {
        "system": "http://id.who.int/icd11/tm2",
        "code": "SP52",
        "display": "Fever disorder with excessive salivation (TM2)"
      }
    ]
  }
}

Semantic Mapping Engine

The NAMASTE ↔ TM2 mapping is powered by a semantic engine that combines vector search, multilingual embeddings, and a logistic confidence scaler.

Pipeline

  1. Take NAMASTE definition (and display text)
  2. Generate embedding with Pinecone-hosted model (e.g. Llama / E5)
  3. Search TM2 index (integrated embedding index)
  4. Pick top K candidates and compute cosine similarity
  5. Scale raw cosine to 0–100 confidence via a logistic function (more intuitive for clinicians)
  6. If confidence < 70% → call LLM (via OpenRouter) to choose the best candidate from short-list

Confidence Interpretation

  • ≥ 85% → equivalent
  • 60–84% → related
  • < 60% → wider / broader mapping
🧠
PHI safety: no patient identifiers are ever sent to LLMs. Only terminology labels (code / display / definition) are used for adjudication.

Offline Mode (No Internet EMR)

For EMRs in low-connectivity settings, the service can run as a local SDK / microservice:

  • Pre-bundled NAMASTE CodeSystem
  • Pre-generated ConceptMap (NAMASTE ↔ TM2)
  • Local lookup and translate functions (no Pinecone / cloud)
  • Optionally packaged as a single executable or Docker image
# Example offline start
node offline-server.js

Versioning & Audit

Each terminology artifact follows India’s 2016 EHR Standards by storing version and provenance.

  • CodeSystem.version (e.g. 2025-11-26)
  • ConceptMap.version with regeneration date
  • Audit metadata per request (token, timestamp, operation)

Error Contract

Errors are returned as simple JSON, and can be wrapped as FHIR OperationOutcome if required.

HTTP Meaning
400 Missing or invalid parameters
401 Missing / invalid bearer token
404 Code not found in terminology
422 Malformed FHIR payload
500 Unexpected server error

Example 404

{
  "error": "No reverse mapping found (ICD→NAMASTE)",
  "code": "SL99"
}
